## 已修复问题

### High：归一化同名列可能被静默选错

材料识别原先把归一化列名直接映射到单个源列；当表中同时存在 `product` 与
`Product` 等归一化后同名的列时，后出现的列会静默覆盖前者。现在保留全部匹配，
出现歧义时阻止计划启动并明确要求用户保留唯一列名。

### High：同一个源列可被复用于多个业务字段

手工或异常 `column_map` 原先可把同一物理列同时映射为多个 canonical 字段，
使风险率、权重或成本字段在错误口径下重复使用。现在确定性计算入口强制
canonical-to-source 一对一，并对不存在或重复的物理列 fail closed。

### Medium：损坏材料会被误报为“尚未上传”

自动登记材料时原先吞掉所有候选文件的读取异常；当唯一文件扩展名错误、损坏或
不可解析时，Agent 会错误提示没有材料。现在会尝试全部候选；若没有任何文件成功，
重新抛出首个类型化摄取错误，由现有材料恢复边界给出可重试诊断。

### Medium：余额金额与余额率的混合明细被不必要地拒绝

VTG 原始余额曲线同时映射 `mob_balance_amount` 和 `mob_balance_rate` 时，原实现
要求每一行两个值都存在。现在逐行选择可用值；两者同时存在时做容差勾稽，两者都
缺失时才拒绝，并在报告中保留混合/勾稽来源。

### Medium：重复客户阶段可能被重复加权

收益测算的客户阶段折叠原先允许同一产品、期间、场景和资产类别下出现重复
`customer_stage`，从而重复计入数据成本。现在阶段值必须唯一，重复时给出明确的
行级错误。

### Medium：报告文本可触发 Excel/XML 边界错误

上传字段和值中的 XML 非法控制字符可能让 `openpyxl` 保存失败，超长文本可能超过
Excel 单元格 32767 字符限制。现在所有文本统一清理非法字符、保留公式注入防护并
在合法上限内截断；新增公式、控制字符和长度回归测试。

### Medium：任务创建/删除可能遗留临时材料目录

对话优先的风险分析任务会自动创建 task-scoped intake 目录。原实现删除任务时不
清理该目录，数据库创建失败时也会留下未归属目录。现在仅对 workspace 自有、
`risk-intake-*`、未被其他任务共享的目录进行安全清理；符号链接只删除链接，
创建失败只尝试删除仍为空的本次目录。

### Medium：样本设计澄清会吞掉材料自动恢复提示

策略主线的成熟样本设计门槛可能在材料已被成功按真实 Excel 格式恢复后立即暂停，
但暂停响应丢失了扩展名纠正提示。现在澄清响应保留结构化 `ingest_notices` 和可见
说明，用户不会因后续治理门而失去前一步诊断。

### Medium：并发生成同一策略报告会受普通 5 秒写锁上限影响

报告发布必须在一个写事务内复核全部治理证据、登记四种格式、写版本和审计，并再次
校验四个文件。CI 高负载下首个发布者持锁超过普通 SQLite 操作的 5 秒默认等待时，
第二个完全相同的发布者会得到 `database is locked`，破坏既有幂等承诺。

修复只提高报告发布事务的有界等待到 30 秒，不改变全局 SQLite 健康契约；新增一个
把默认等待压到 10 毫秒、由另一写者持锁 100 毫秒的确定性回归，旧实现稳定失败，
修复后通过。原双写者完整用例继续验证只产生一个报告版本和一条审计。

### Medium：策略编译 Prompt 文本与审计版本漂移

策略主线已经改变自然语言策略编译 Prompt，但 registry 仍记录 version 50，锁定
哈希也停在旧文本。这样运行记录会把新 Prompt 错标成旧评测基线。现在同步升级到
version 51 并锁定当前哈希；Prompt registry 和策略编译契约定点回归均通过。

### Medium：损坏策略快照泄漏治理层内部异常

风险分支复测主线时发现，策略生命周期或 canonical DSL 损坏会从授权绑定读取中
泄漏 `ValueError`，而不是稳定的授权拒绝。现在治理服务把无效元数据、生命周期
清单和策略定义统一转换为 `ApprovalBindingError`，继续保持 fail closed。

### Low：展示、记忆和回归覆盖缺口

- `_spread` 指标按百分比展示，不再作为普通小数。
- 风险分析经验的公开导出、记忆管理筛选项和说明文案与后端类别保持一致。
- 恢复此前被风险分支误删的三组 Vintage 材料恢复参数化用例。
- 更新样本设计引用、决策点/确认门和双写策略生命周期后的旧测试契约。
- 任务创建失败的 intake 目录回收、跨任务 dataset 拒绝、混合余额来源、重复阶段、
  字段歧义和报告安全均补充回归覆盖。

### PR 门禁：单作业超过 100 分钟被取消

首次 PR CI 中，安全、策略 smoke 和 PMML/JVM 三条独立门禁均通过；`checks`
不是测试失败，而是 9747 个已收集用例集中在一个 hosted runner 上，在 100 分钟
上限被平台取消。为避免用“提高超时”掩盖反馈过慢，PR/push 门禁改为：

- 静态检查、JavaScript 语法和差异完整性独立执行；
- fast 测试按稳定 node id 哈希拆成 4 个并行分片；
- 汇总 `checks` 只有在静态检查和全部 4 个分片通过后才通过；
- 手工 full release gate 仍执行未分片全套，不删除 slow/e2e/llm/PMML 覆盖。

未过滤收集共 9747 项；PR fast marker 过滤后选中 9521 项，四个分片分别为
2411、2339、2423、2348 项，合计无遗漏。其余 226 项属于
slow/e2e/llm/PMML marker：策略 smoke 和 PMML 由独立门禁执行，未在 PR 中执行的
slow/e2e/llm 仍由手工 full release gate 覆盖。这里没有删除测试；分片参数缺失、
越界和非整数均 fail closed。

## 保留边界

- Agent 负责理解目标、索要材料、解释结论和驱动 Workflow；风险率、收益率、权重、
  周转和报告数值始终由确定性 Tool 计算。
- 风险分析记忆只保存有界汇总、口径、红旗、字段映射和报告文件名，不保存原始行、
  客户标识、完整报告、本地绝对路径或连接信息。
- 单份 VTG 组合报告不混合多个截面或场景；收益测算不把缺失成本静默当成 0。
- 该分支交付的是 V2.x 能力，不把已确定功能推迟到 V3/V4。
