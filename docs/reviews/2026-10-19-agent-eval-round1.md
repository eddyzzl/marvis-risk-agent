## 2. P0 问题（先修）

1. **组合分析：平均迁徙率矩阵算错**（S9，确定性指标）
   - 现象：
     - 61-90 行只有 charged_off 66.7%，charged_off 行只有 33.3%，行和都不到 100%。
     - 用原始数据重算，两者都是 100%（2/2、1/1）。
   - 根因：`marvis/packs/analysis/flow.py:196` 的 `avg[i][j] = sum(cell_values) / len(cell_values)` 对所有月份对取平均，把该起始状态没有出现的月份当成 0% 计入了分母。
   - 影响：下游“各状态到损失态的吸收概率”（current→损失 86.8%）和“逐月预期损失”都基于这个矩阵。
2. **模型开发：交付的不是用户确认的实验，解读与平台结果矛盾**（S4）
   - 用户确认的实验：
     - 「选择实验」门里确认的是 experiment_11bd…（status=selected，OOT KS 0.568 / Test KS 0.571 / OOT AUC 0.82）。
     - 它带 overfit_flag=true（训练与测试的 KS 差 0.23），界面没有提示。
   - 实际报告与交付的实验：
     - 用的是两分钟后新建的 experiment_3f54…（status=handed_off，只有训练集指标，test/OOT 全为 null）。
     - 界面写“用户指定实验”，并给出“建议可审批”。
   - 解读：「模型效果 Agent 解读」三次都写“oot_ks、test_ks…均为 null，证据不足”，而同一张卡上就显示着 0.568 / 0.571。
   - 待查：3f54 疑似是选择后重新拟合的最终模型。无论原因，都需要：
     - 交付对象与用户确认的对象一致，或明确说明并给出留出集指标；
     - 解读必须读用户所选实验的指标。
3. **模型验证：报告修订会清空草稿；空结论能“生成”却下载不了**（S2）
   - 修订请求被拦截时，回复“当前报告字段已保留”，实际最终验证结论、压力测试总结、压力影响建议三段全变成“待补充”。`/report-fields` 里为空，刷新也找不回。
   - 三段为空时点「确认并生成报告」没有任何提示，对话里显示“报告已生成”，产物卡出现。但预览和下载都返回 409：“请先确认三段报告结论”。
   - 根因：确认动作不检查结论非空，下载闸门 `marvis/api_report_helpers.py:41` `require_confirmed_agent_conclusions` 要求非空（`marvis/agent/service.py:790`），两道闸口径不一致。
4. **多模型验证：批量视图的字段确认表单随轮询重绘**（S5）
   - 表单约每 1.4 秒整体重绘。
   - 用户改的值被冲掉：把训练集取值改成 train_EDITED，4 秒后变回 train。
   - 按钮元素被替换，两次正常点击都没发出确认请求。
   - 整批停在“待确认 · 确认字段”，B 一直排队。
   - 单任务没有这个问题。
5. **模型验证：任务里无法补传或替换材料**（S1）
   - 材料不合格（字典缺 importance）时：
     - 检查器里只有“定时分析与反馈处置”；
     - 失败卡的「重新选择验证材料」弹窗只有下拉，没有上传。
   - 补好的文件传不进来，只能另建任务。
6. **策略开发：澄清死循环，无法开始**（S8）
   - Agent 先问“审批（approval）还是拒绝（reject）”。
   - 用户回答“准入就是审批策略，没有基线”，被路由拒绝：“我还不能安全确定这句话要进入哪条流程”。
   - 换口令格式后，又要“objective=max_approval 或 max_profit”。
   - 用户回答“坏账不超过 5% 前提下尽量提高通过率”后，又从头问审批还是拒绝。
   - 首页已提取的约束（通过率≥60%、坏率≤5%）没被使用。
7. **Agent 编造平台要求**（S1）
   - 用户问“数据字典需要哪些列”，Agent 列了 10 类“建议至少补齐”的列（字段类型、取值范围、缺失定义、衍生逻辑、合规标识……）。
   - 平台并不要求这些；真正必填的 importance 一个字没提。

## 3. P1 问题（按类别）

### 3.1 意图理解

- **拼表被猜成特征分析**：“把这两张表拼起来…征信特征表按客户关联过来”被“特征”二字带偏，猜成特征分析（S6）。
- **拼表键没用用户说的口径**：用户说“按客户关联”，两表都有 cust_id，平台却选了 mobile=mobile_md5（指纹不一致、类型不一致），没解释为什么不用 cust_id（S6）。
- **“对两个特征分箱”被执行错**：用户说“那先对 sig1 和 score 做分箱，然后生成报告”，被执行成“调整参数 {'features': ['sig1','score']} 并重算特征指标”。其余 5 个特征从分析里消失，最终报告只剩 2 个（S3）。
- **用户的明确要求被忽略**：
  - 特征分析：用户点名要“稳定性”，计划不含 PSI，样本里明明有 split 和 apply_month（S3）。
  - 模型开发：用户说要看 OOT KS，建模协作台第 1 步默认“不设置 OOT”，也没有“沿用已有 split 列”的选项（S4）。
- **行为卡被写成支用阶段**：用户说的是“行为评分卡”，叙事和报告通篇写“支用申请阶段”（S2）。
- **结果问答接不住**：
  - 特征分析追问“为什么没算稳定性”，只回了路由理由（“属于疑问和新增分析诉求，未明确授权继续当前节点”）（S3）。
  - Vintage 完成后问“哪个月最差”被拒（S7）。
  - 首页超范围请求也没有说明做不到。
- **修订意图靠关键词，且漏词**：`marvis/agent/service.py:491` 的修订动词表没有“修订”，而卡片按钮「请 Agent 修订」预填的正是“请根据当前证据修订…”，所以按钮带出来的话永远命中不了修订路由；“补上、写上”这类说法也不行。句子里提到 KS 又会被指标防护误拦（“KS…不能按对话改写”）（S2）。

### 3.2 执行和流程

- **创建后界面不刷新**：首页创建后，Agent 模式点「稍后选择」关掉材料弹窗（S1）、手动模式点「确认材料并继续」（S10），都会回到首页，侧栏也没有新任务，刷新才出现。Agent 模式点确认（S2）正常。
- **确认门按钮消失**：在确认门停着时追问两句，分箱确认卡底部的两个按钮从 DOM 里消失，状态仍是“待确认”（S3）。
- **重规划失败给死路**：首次重规划就说“重规划预算用尽”，还让用户去点不存在的「调参重算」入口（S3）。
- **自动审查无效**：多模型批量开着“自动审查”，每个模型仍停在字段确认（违背“多模型创建后自动走完全流程”）（S5）。
- **手动“运行”误报**：通过链接直接打开手动任务后点「运行」，只有一条隐藏提示“请先选择当前任务。”，任务明明是选中的（S10）。
- **报告结论遗漏最大风险**：最终验证结论没提压力测试“两类特征剔除后 KS 1.0→0.0、高风险数据源”这个最大的风险（S2）。
- **批量叙事退化成套话**：批量模型 1 的效果与稳定性叙事退化为通用模板（“请以平台已计算的 KS、AUC…为准”），界面没有提示这是降级文案（违背“禁止各模型相同套话”）（S5）。
- **自相矛盾的交付状态**：「候选模型对比」汇总写“不可交付、缺少可交付模型产物”，同表那一行写“可移交”（S4）。

### 3.3 Agent 解读质量（共性）

- **证据缺口导致 LLM 说“平台没给”**：
  - 特征分析、拼表、建模的解读都反复出现“未提供命中率、重复键、行数膨胀、样本外表现、历史记忆”，与当前任务无关。
  - 字典缺列的原因（`blocking_errors`）、压力测试类别名（行为/负债）都没进证据，于是 LLM 说“平台未提供”。
- **事实性错误**：
  - “单值率 0.21% 说明取值高度集中”（说反了）；
  - “本次为 V2 流程，不涉及 Notebook 与 PMML 的分数一致性验证”（错，这正是模型验证主线）；
  - 编出“存量在贷客户坏样本率天然偏高”的解释。
- **前后矛盾**：同一任务里先说“区分能力良好”，后说“KS=1.0 暂不可采信”；说“验证输入契约仍待确认”，其实用户已经确认过。
- **该有解读的地方没有**：Vintage、组合分析全程没有一句结论，用户的问题没得到回答。

### 3.4 操作冗余

- **模型开发**：训练前要确认 6 次，全程 9 次。同一个四步“建模协作台”出现 3 次：第一次点“确认方案，开始执行”只是重切了样本，然后再摆出整套向导。
- **材料弹窗**：模型验证在材料已经全部自动对上时，仍弹出「选择验证材料」要求再点一次。
- **风险分析**：首页已选“标准 Vintage”、已传面板，进任务后又问一遍分析类型、又要求上传。
- **组合分析**：口径表单的列名全空，灰色占位恰好就是真实列名，看起来像填好了，提交时报错。平台没有按上传文件的列自动预填。
- **多模型**：首页不能把附件分给不同模型，要去高级设置逐个添加、重新上传；模型 1 带着全部 8 个文件，没法单独移除。同名文件被静默去重，丢掉 4 个文件没有任何提示。

## 4. P2 / P3 问题（摘要）

- **内部信息外露**：
  - 工具名 scan_materials、woe_encode_categorical；
  - 键名 material_data_dictionary、required_materials_complete=false、pending_confirmation（needs_confirmation=true，revision 1）；
  - Python dict / list（`{'features': [...]}`、`['score']`）；
  - result_dataset_id、policy_fingerprint、experiment_…、artifact_…；
  - 服务器绝对路径；
  - 英文原文：“feature metadata: metadata file: missing … importance column alias”、“recipe target family does not match `binary`”、“univariate KS 0.448 >= 0.4 — suspected target leakage”；
  - 状态词：candidate / medium / deteriorating / sparse_month / high_concentration；
  - 一整列字面量 None。
- **数字格式**：全精度浮点（ks=0.40096692502494047、train_ks 0.5087659574468084）、金额 4 位小数、feature_count 6.0000；KS 一处显示 100.0、另一处写 1.0。
- **表单原样显示 JSON**：「模型参数来源」「特征元数据列」两个下拉显示原始 JSON。“验证字段候选”表行重复、值带引号。
- **重复内容**：“数据质量红旗”同一张表出现 3 次；“PMML 部署可用”在一段里重复 4 次；“未配置业务验收标准。”反复出现且没有解释。
- **状态不一致**：
  - 报告还没生成，右栏子任务已全部打勾；
  - 模型 1 实际在等确认，模型框写“执行中 · 报告结论”；
  - 右栏写“PMML打分测试”，模型框写“确认字段”；
  - 字段确认后，扫描卡和头部仍是“待确认”。
- **按钮状态**：「全部确认」禁用时外观和可点按钮一样，原因只在悬停提示里；已完成步骤的「生成」禁用时提示“请先完成上一步”。
- **实体抽取**：
  - 模型名“是我们新上的行为评分卡 模型验证”“LR模型验证”；
  - 任务名“特征哪些能用”“两张表拼起来 特征分析”；
  - 建模交付后侧栏多出“贷前A卡 建模 · artifact_5995…”两个任务。
- **文案**：“开始前还需要：负责人”，字段名却是“验证人员”。
- **特征分析漏报**：`score` IV 1.61、KS 0.46 没有泄漏提示（建模时又判为泄漏，两处口径不一致）；类别列 channel 被静默排除。
- **组合分析**：只有两个各占 50% 的分群也被判“高度集中”；“迁徙热力”只有表、没有热力图。
- **Vintage**：没有 cohort×MOB 曲线图，“参考 MOB”是第几期没说明，没有报告下载。
- **拼表**：结果只给 parquet，文件名是内部 ID；表名显示为哈希 parquet 名或数据集 ID。
- **性能**：空闲等待时每 10 秒约 49 个请求（7 个接口各轮询 7 次）；同一 GET 在几毫秒内连发 10 次。

## 6. 建议的修复顺序

1. **计算与选择正确性**：迁徙矩阵（P0-1）；交付实验与解读证据（P0-2）。这两项直接影响结论，先修并补测试。
2. **流程卡死**：
   - 报告修订清空草稿与生成/下载闸门口径（P0-3）；
   - 批量表单重绘（P0-4）；
   - 任务内补传材料（P0-5）；
   - 策略澄清循环和结果问答（P0-6、3.1）。
3. **Agent 证据与解读**：
   - 把 blocking_errors、类别名、用户目标（KS 门槛、用途）放进证据；
   - 解读去掉跨任务的模板套话；
   - 修订意图改为“结构化按钮 + 宽松识别”；
   - 禁止编造平台要求。
4. **减少确认**：
   - 建模协作台只出现一次；
   - 材料全部对上时跳过弹窗；
   - 首页已选的类型和材料不再重问；
   - 组合口径按列名预填；
   - 自动审查在批量里真正生效。
5. **前端改版**：U1–U18、R1–R2，以及 4 节里的展示问题（内部信息外露、数字格式、表格改图）。
