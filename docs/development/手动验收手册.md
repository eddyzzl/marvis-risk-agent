# MARVIS 手动验收手册

本手册用于用户在独立验收工作区核对 MARVIS 的软件行为，再单独决定业务效果和机构生产是否通过。开发者的本地测试、合成参考服务和截图是辅助证据；用户的验收结论需另行登记。验收使用的发布版本、源码摘要和环境须记录，不应覆盖日常工作区。

验收依据为 [产品路线](../roadmap.md)、[本轮发布说明](../releases/V2.7.1.md)和各模块公开合同。正式软件冻结方法和门槛列于第 4 节；使用时须自行事前冻结任务、独立答案、责任和台账，原身份、门槛和失败记录不得改写。配套 [验收记录表](手动验收记录表.csv) 可逐行填写，空白表示尚未验收。

## 1. 验收前准备

1. 留存日常工作区备份，另建空白验收工作区；不要直接在原业务任务中测试撤销、回滚和故障。
2. 记录候选源码摘要、依赖环境、操作系统、机器配置、浏览器及验收时间。分辨率分别使用 1440、1600、1920 宽桌面。
3. 在设置中选择获准的 DeepSeek 配置。密钥只在本机设置保存，不写入验收记录、截图或报告。用户主动输入指令经敏感检查后可以发送；样本、文件正文、凭据及报告全文仍不得出站。
4. 为业务复核准备有明确实体、事件时间、可得时间、标签及成熟口径的脱敏材料。合成材料要标记“合成”；无法证明的字段写“未知”。
5. 需要复核人或管理员的操作，使用相应独立会话。不要在同一会话中改角色来冒充双人复核。正式机构模式使用已配置签发方和登记身份；本地参考角色仅用于软件操作检查。
6. 建立单独的原件保存目录。每次检查保存任务编号、计划编号、版本、实际操作时间、服务回执、下载产物和必要截图；对原件计算摘要。失败、跳过、预算不足及环境错误照实保留。

技术启动示例在文末。先确认所安装的版本与验收记录一致；另一安装版的结果不能替代当前版本的验收。

S12/S13 从全新工作区开始时，先按 [验收合成材料准备](验收合成材料准备.md) 创建本地合成 SQLite 来源和合法 `sql_sources.json`，再使用其输出的工作区启动应用。该说明也列出验证材料、历史映射、盲 OOT、身份与模块入口；不复制日常来源配置或真实凭据。

## 2. 每项检查的判定方法

先写下预期结果，再操作。正常检查须同时满足：任务成功、原生执行记录存在、下载内容正确、页面状态一致。点击成功、HTTP 成功、Agent 文字“已完成”不能单独作为通过依据。

拒绝检查须核对拒绝原因，并确认没有启动不允许的工具、读取数据或产生外部动作。恢复检查须保留首次失败和恢复回执；同一业务请求不能产生第二次安装、决策、扣款、催收动作或版本发布。未知状态先读取和对账，不能直接重复提交。

结果填“通过 / 失败 / 未执行 / 不适用”，同时写证据位置和原因。只有原支持边界明确排除的项目才可填“不适用”；不能用它消除应交付项目或失败分母。

## 3. 软件操作检查

下表给出建议检查顺序，各项按自己的前置条件使用独立任务；尤其 S16 必须另建未开始开发的空白建模任务，先封存再登记开发材料，不能接着使用 S15 的任务。具体字段、阈值、金额单位和时间口径由验收材料预先冻结，不使用临时猜测值。

| 编号 | 操作 | 必须看到的结果 |
| --- | --- | --- |
| S01 | 创建单模型验证任务，提交符合 Notebook 契约的材料和带 importance 的字典 | 手动和 Agent 两种模式均可运行；仅生成该模型 Word/Excel |
| S02 | 创建两个以上模型的验证批次 | 自动完成审查，各模型进度独立；批次名称一致，额外生成汇总 Excel |
| S03 | 查看分数一致性、KS/AUC、PSI、Lift 和压力测试 | Notebook 内存分与 PMML 分实际比较；Lift 同时解释分箱排序和头尾区分度；失败项标红加粗 |
| S04 | 缺失 importance、损坏 Notebook、缺少契约变量、PMML 分不一致 | 清楚拒绝或判失败，不静默补 importance，不伪造通过 |
| S05 | 编辑报告草稿表格，确认后生成；再在对话中修改叙事 | 下载内容与确认版本一致；修订报告不重新打分，不改变确定性指标 |
| S06 | 多模型全部确认，同时切换模型与任务 | 原草稿、任务和模型版本准确绑定；旧响应不覆盖新任务 |
| S07 | 使用自然语言导入、JOIN、特征分析、建模、策略和监控 | 形成实际治理计划并执行工具；字段和结果可追溯，无裸文件内容出站 |
| S08 | 在主动指令中放入合成密钥、连接凭据或客户明细格式 | 出站前明确拒绝；模型端收到的请求数为零 |
| S09 | 模型超时、无 usage、达到调用或 token 预算 | 原失败保留；不释放未知用量预算，不靠重试绕过总额；费用未知明确显示 |
| S10 | 导入数据，确认字段别名并改名，再切换任务、刷新页面 | 物理字段与业务别名映射一致、持久；碰撞、歧义和旧版本确认被拒绝 |
| S11 | 确认字段风险方向，再用自然语言编译策略 | 仅使用已确认且来源匹配的方向；未知字段不按名字猜测；确认者和别名正文不传模型 |
| S12 | 按合成材料准备说明配置全新工作区的本地 SQL 来源，再通过表单和自然语言查询、预览并导出 | 待确认时尚未执行；确认后实际查询注册为受治理数据；导出行和预览相符，凭据不进入日志或页面 |
| S13 | SQL 写操作、多语句、越权数据源、超时或行数超额 | 执行前拒绝或在限制内终止；没有写入，旧任务不收到迟到结果 |
| S14 | JOIN 一对多/多对多、空键、重复实体；执行标签和特征流程 | 有连接放大诊断、成员身份和样本口径；按原独立答案复算一致 |
| S15 | 上传已有分组（含非默认列名及 Development/holdout/time_oot 别名），再测双分组列、未知成员；另按明确事件日期及预先冻结比例划分时间 OOT | 已有分组逐行成员、计数、角色及摘要前后一致，不重切或丢 OOT；双候选或无效成员先澄清，不产生派生分组；新时间切分同日不跨边界，明确开发集/OOT 隔离和实体交叉 |
| S16 | 另建未开发的空白建模任务，用全新未暴露材料和保管/开发/评估独立会话，先封存 OOT，再仅登记 train/test、训练并冻结原生候选，评估一次并重放原请求 | 不复用 S15 任务或历史已消费材料；开发、Agent 和评估流程在冻结前不可消费 OOT；评估绑定候选/数据摘要；重放只读回原回执，不再次读取原始 OOT 或重新计算；新候选重用已消费封存集被拒绝 |
| S17 | 明确保留所选原候选、不重训；另用独立任务明确执行 train/test 开发集重训，分别建立监控基线 | 保留候选时模型和产物身份不变、真实留出指标保留；重训时产生完整开发集子模型，不虚构其 test/OOT 指标；两种基线分别绑定实际选中模型的分数和特征 |
| S18 | 使用常数分数、重复分位点、漂移特征和未成熟标签 | 分箱合法且可复算；PSI/CSI、样本成员和标签成熟范围准确，未知不充当零 |
| S19 | 策略工作台进行规则挖掘、分群、额度、定价、双人群和 swap 分析 | 各工作区共用原生治理，输入口径明确；结果与独立手算一致 |
| S20 | 长任务暂停、续跑、取消、切换 A→B→A、刷新恢复、改当前数据 | 具有检查点的搜索状态与输入 producer 绑定持久；旧提案失效；取消保留已提交的输出/副作用；不可抢占的 Tool 明确说明 |
| S21 | 导入历史模型/资料，映射历史样本与字段 | 有显式字段和时间映射；资料缺失、无法解析及分数不可得准确提示 |
| S22 | 对独立 asset/OOT 样本分析稳定性、分群×月及金额影响 | 绑定独立样本和金额单位；原观测、假设与未知分开；验证不自动转成采纳或上线 |
| S23 | 下载策略 Python、SQL、JSON 和独立验证报告 | 三种产物对同一冻结样本逐行输出相等；版本、默认行为和字段映射一致 |
| S24 | 发起策略晋级，由另一会话复核，再由管理员安装、健康检查、激活 | maker/checker 职责分离；实际包、回执和各环境版本一致 |
| S25 | 在线单条/批量决策、影子模式、同一 request 重放 | 分数/规则/原因/包摘要可核对；重复请求返回原结果，不产生第二个业务决策 |
| S26 | 升级后按环境回滚，再重启服务读回 | 恢复准确旧版本；其他环境不受影响；各环境实际活动版本持久 |
| S27 | 安装或激活已提交但响应丢失，查询原操作并恢复 | 恢复仅对账已发生动作，不重新提交第二次安装或激活 |
| S28 | 用自然语言准备调度，核对冻结日历和来源，人工确认发布 | 不清楚时间/水位/成熟口径时先澄清；确认绑定当前版本、主体和合同指纹 |
| S29 | 周期监控补跑、通知送达/失败重试、停用再恢复 | 实际日历、原生结果与配置通道回执可核对；未配置外部通知不称送达；停用期间不执行，补跑受预算约束 |
| S30 | 策略红灯后分别选择继续观察、新版本、调整阈值 | 处置有人工理由和准确窗口/计划绑定；调整阈值走新原生审批，重放不重复变更 |
| S31 | 运行月度组合复盘 | 迁徙、Vintage、损失/集中度及报告来自实际工具；期数、金额和成员逐项可复算 |
| S32 | 回传实际决策标签，运行反馈监控 | request、决策包和输出摘要与原决策一致；未来/未成熟标签不进入指标，重复标签不重复计数 |
| S33 | 历史决策回放，含迟到回款、冲正、分期和不同时间窗 | 现金流和截止时间可对账；事实、假设与观察差异分开，不宣称因果收益 |
| S34 | 在历史回放中使用事件模型包 | 显式映射原生事件引用、主体及当前有效授权；缺少映射或授权不能伪造特征 |
| S35 | 登记数据服务、授权依据和权限；查询历史记录或参考 HTTP | 实际服务/登记样本生成原始回执；无结果、部分覆盖、熔断和模式漂移准确展示 |
| S36 | 查询超时、响应丢失、撤销/过期授权后读取和恢复 | 未知结果先对账；撤销立即阻止后续读取/调用；原错误保留，没有再次越权请求 |
| S37 | 登记并导入事件/覆盖快照，准备事件窗口与关系回放，人工授权 | 原生 PlanValidator 和 ToolRunner 实际执行；结果绑定源、主体、时点及授权 |
| S38 | 事件晚到、未来可得、包含当前事件、覆盖不足和大整数求和 | 按显式 PIT 口径复算；未知保留；大于 2^53 的整数在原生计算中精确保留 |
| S39 | 催收候选政策→数据映射→独立审批→队列→参考执行 | 受保护参考动作、成本与回收记录可核对；候选/批准/执行分开；参考结果不代表真实触达或收益 |
| S40 | 重放、取消或恢复催收批次，触发越权/金额单位错误 | 不重复动作；取消和失败可追溯；错误口径执行前拒绝 |
| S41 | 配置机构签发方，使用短期断言登录；登出、过期、重放 nonce | 真实登记主体/角色生效；调用者自报角色不生效；旧会话失效后不能继续 |
| S42 | 两用户分别创建/授权/撤销任务，尝试跨任务读取计划、数据和产物 | 列表与直接访问都遵守资源授权；管理员也不因角色自动得到所有业务内容 |
| S43 | 机构模式重启中断任务，并在重启前撤销执行者权限 | 仍有授权的原身份绑定可恢复；无授权或未绑定身份停为失败，零 Tool/Hook，不补造授权后重跑旧任务 |
| S44 | 两个工作区同步原生二分类 LR、策略及签名 Workflow，重放请求并回滚 | 仅 median-imputer→StandardScaler→LR 模型合同；原生预测相同，额外预处理及其他族明确拒绝；精确版本、签名和节点撤销按 CAS 生效 |
| S45 | 信任发布者，安装签名 Plugin/Workflow，审核新增权限，再回滚 | 审核当前签名内容和权限差异；准确旧版本保留；计划固定原工具版本 |
| S46 | 签名被篡改、发布者撤销、权限改变、旧确认或直接 unsigned reload | 执行/激活前拒绝；新权限须重新审核，无旁路安装或静默覆盖 |
| S47 | 设置 macOS 强隔离，运行支持的第三方 input-only 计算 | 实际原生隔离 worker 执行；模式持久，切换 Notebook 环境不丢失 worker 模式 |
| S48 | 隔离内尝试读取工作区/凭据、网络/IPC、fork、超时或巨量输出 | 不越过限制，资源超额终止并回收；不支持的权限/平台在 worker 启动前明确拒绝 |
| S49 | 未配置机构适配器时打开接入页 | 显示未配置，不声称已经接通机构，不向任意地址发请求 |
| S50 | 配置固定参考适配器，注册/晋级/部署/激活/回滚/查询，再撤销源授权 | 模型登记 storage_only，远端部署 rule_only；原件、版本、读回和 CAS 一致；源授权撤销后原/新 operation 查询均拒绝且远端请求与效果不增加 |
| S51 | 机构适配动作已提交后丢响应，再按原 operation 读取/恢复 | 仅读取远端实际状态；一次 POST 副作用，不因未知状态重新执行 |
| S52 | 源码/数据/文件在审核后改变，再确认或恢复 | 指纹漂移和旧确认被拒绝；不偷偷使用新内容完成旧任务 |
| S53 | 三种桌面宽度检查上述页面、错误、长任务与下载，再刷新 | 页面无横向溢出、遮挡和脚本错误；表单保留输入，状态/证据/下一操作可见 |
| S54 | 保留失败后汇总验收，复核下载内容和原件索引 | 软件、模型效果、历史和生产结论分别记录；没有用测试数量代替业务通过 |

机构身份与双实例同步从设置中的「身份与资源授权」「跨实例交接」入口配置，参见 [身份与同步运行说明](../institution-identity-and-sync.md)；签名 Plugin/Workflow 从设置中的「签名与版本」入口操作，参见 [签名能力合同](../governed-capability-contract.md)。外部适配器操作需先选择受治理任务，再在任务工作台展开「机构服务接入」并点击「读取服务配置」；参考服务须按协议先启动。没有配置时先做 S49，不臆造机构端点。

## 4. 正式软件冻结验收

上面 54 项操作检查不自动满足原隐藏软件验收的数量要求。正式验收要在执行前冻结隐藏任务、独立答案、原件保存和复核责任安排。若没有第二位独立复核人，可以先完成个人手动检查，但不得把它写成双人独立验收已完成。

- 正常集 64 例，8 个原家族各 8 例；总通过至少 61/64，每家族至少 7/8。
- 边界集 20 例，逐例通过；恢复集 16 例，须逐例完成原要求。
- 在线决策、连接器/反欺诈、催收三个扩展，各至少 10 例正常和 1 例独立负例；正常按原 95% 门槛取整，不将负例混入正常分母。
- 20 个关键场景另外各重复 3 次，共 60 个槽位，至少 57/60；重复场景不冒充新独立案例。
- 至少 133 个不同案例、193 个执行槽位；严重安全或证据错误必须为零。
- 失败、skip、预算不足、环境/评分错误保留原分母和原件；旧失败不删除，新行为采用另有版本的案例，不改原答案。

复核内容包括：数学结果、来源与产物身份、权限、时间穿越、重复副作用、虚假完成。读回产物正确并不能替代后三项安全证据。缺少原始事前快照、可信责任绑定或可得时间证据时，应填未证明，不能补造旧记录。

性能验收先冻结机器、候选版本、数据规模、并发量和经你批准的 SLO。分别测试冷启动、持续负载、并发和恢复，记录 p50/p95、错误、重试、用量和成本。没有批准 SLO 时只报告测量，不宣布性能达标。

## 5. 历史业务验收 H

先事前登记实体、事件时间、数据可得时间、标签成熟口径、适用人群、原模型与候选的身份、分组规则、特征和调参预算、指标及独立业务门槛。留出时间段和实体边界须明确；旧模型的原训练成员或可得时间无法证明时，保留“未知”及其对结论的限制，不能补造记录。

使用全新未暴露的独立 OOT，按 S16 的封存、冻结和一次评估流程比较原模型与候选，并保存两者逐项指标、样本身份与原件摘要。达到预先冻结的比较门槛才可签“效果更好”；未达到门槛照实失败。若继续训练或调参，必须另备未消费的独立材料，不能把已查看的 OOT 重新当盲验收。还需核对实际操作工作量、收益/风险口径和适用业务，观察、模拟、假设和因果结论分别记录。

## 6. 机构生产验收 P

通用参考服务的接口通过只证明协议和恢复机制；真实机构 P 仍需目标身份源与接口、受控数据、批准 SLO、业务负责人和批准流量。未配置目标系统时保持“未执行”，不能以本地参考服务代替。

取得目标系统后，按 [机构适配器协议](institution-adapters-protocol.md) 完成证书/固定起源/本机凭据配置和全部正向、拒绝、失联、提交后丢响应、撤销、精确回滚检查。注册 opaque 模型不代表可执行该模型；通用模型登记仅支持不透明 `storage_only` 存储，远端参考部署目前只支持声明的 `rule_only` 运行边界。强 worker 隔离的支持边界见 [运行说明](../native-worker-isolation.md)：当前 macOS、非内置、input-only 计算；不将 Linux/Windows 未验证或受信宿主内置工具说成已经具有该隔离保证。

随后批准小流量试运行，核对真实环境活动版本、决策、告警送达、回滚和成熟业务结果。H、P 签字分别留存；没有批准流量不做真实客户试运行。

## 7. 留存与签字

每次验收建议目录：`日期/候选身份/案例编号/`，分别保存预期、原始执行、截图、下载产物和复核结论。原件目录不存模型密钥、会话 cookie、原始客户明细或私钥；敏感原件按本机权限另行保管，只在索引记录摘要和必要标识。

填写记录表后，分别给出软件检查、正式软件冻结门、历史业务、机构生产四项结论，以及尚未执行的项目。结论附姓名、实际责任、日期和证据索引。只有对应层全部门槛满足才签通过；代码存在或开发者复验通过不代表你已验收。

## 附：本机技术启动

在候选目录使用一个全新验收工作区运行，端口请选本机空闲值：

```bash
mkdir -p "$HOME/MARVIS-验收"
MARVIS_ACCEPTANCE_WORKSPACE="$(mktemp -d "$HOME/MARVIS-验收/workspace.XXXXXX")"
python -m marvis version
python -m marvis serve \
  --workspace "$MARVIS_ACCEPTANCE_WORKSPACE" \
  --host 127.0.0.1 --port 8860
```

浏览器打开 `http://127.0.0.1:8860`。不要从不同候选启动宿主和子进程；更换源码后重启应用再验收，保留更换前失败。需要真实机构模式、签名信任或机构适配配置时，先遵守各模块安装/运行说明，再进行本手册的对应检查。

做 S12/S13 时，将示例中的 `--workspace` 替换为 [合成材料准备](验收合成材料准备.md) 实际输出的新工作区，或直接使用其输出的启动命令；来源配置不会自动出现在另一工作区。
