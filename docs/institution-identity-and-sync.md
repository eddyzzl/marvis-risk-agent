# 机构身份、资源授权与实例交接契约

这是可选的本地参考实现。`trusted_local` 保留既有本地工作流；`institutional` 使用持久主体、签名登录和准确资源授权。参考签发方与双实例检查不构成外部机构身份接入、机构授权或业务投产验收。

## 身份与登录

管理员先登记 Ed25519 签发密钥及主体的服务端角色，然后确认模式与 audience 的配置版本。存在未绑定身份的非终态旧计划时，模式切换拒绝，不能给旧计划补一个推测的身份。机构模式强制签名 Plugin / Workflow 版本准入，不接受本地角色声明降级这一要求。

`POST /api/institution/challenge` 返回一次性挑战；签发方签署严格对象 `marvis.identity-assertion.v1`，字段仅为 `schema_version/issuer/subject/audience/nonce/issued_at/expires_at/key_id/algorithm`。`algorithm` 必须为 `Ed25519`，签名覆盖 UTF-8、键排序、紧凑 JSON 的准确字节。有效期至多 300 秒，挑战至多 120 秒，nonce 在事务中仅消费一次。该协议不是 OIDC/SAML 的实现，也没有假设机构已经完成 subject 身份审核。

登录会话是短期、HttpOnly、SameSite=Strict 的随机 cookie，数据库只存 token 的哈希。每次请求重新检查主体、会话、签发密钥、有效期及撤销；角色从持久主体读取，不使用 assertion 或业务 body 的 role/actor。模式切换、登录和退出触发界面缓存清空。部署原有的同源与本地 token 边界继续适用。

## 资源边界

任务所有者在原生创建事务中绑定。数据集、模型/任务/策略产物、计划、实验、策略及已有 HTTP 别名通过真实数据库归属继承任务授权；准确资源可以另设读取、修改、执行、授权、审批权限与失效时间。授权和所有者变更采用版本 CAS。管理员角色并不自动获得所有任务的业务读取权限。

跨任务任务列表、模型注册视图及生产审批列表先按可见资源过滤再分页。内容哈希去重不能借另一任务的注册信息绕过权限。原生数据读取只接受已授权注册路径，或当前已授权任务的原生上传/处理暂存位置；不能把整个 workspace 挂载成机构数据权限。

原生计划冻结创建者，执行、恢复及子进程重新检查该身份当前的任务授权。内置调度调用冻结已消费的 schedule-run、当前租约、服务器 execution actor、任务、安装工具声明与输入哈希。仅伪造 invocation ID 或 `operations:` 前缀不能取得内置 worker 的宿主访问权限。服务主体可获得读取/执行权限，不能取得人工审批、角色登记或人工确认能力。

启动恢复只读取中断计划 ID。有效身份在冻结身份范围内恢复；已撤销或无身份绑定的中断状态以宿主维护权限停为失败，不读取业务结果、不重新执行 Tool 或 Hook。任意 Notebook、未注册本地路径导入、未知 HTTP 入口与未安全挂载的第三方能力在机构模式明确拒绝。可信内置工具仍在受治理的宿主执行面运行，不能称为全部具备操作系统隔离。

## 双实例交接

`/api/instance-sync` 使用独立实例节点密钥。节点私钥只在本机权限为 0600 的文件中保存，以完整文件原子发布；公钥由接收实例的人类管理员显式信任。签名覆盖准确接收节点、类型、名称、版本、材料哈希、权限与到期时间；不是把来自对端的文件路径或 pickle 当作可信模型。

交接协议 `marvis.instance-resource.v2` 把准确材料 UTF-8 JSON 字节封在 `base64.canonical-json.v1` 编码对象中，避免浏览器解析后把 `0.0` 改成 `0` 或重写指数格式。签名认证编码对象的完整哈希；接收后先验证签名、8 MiB 请求/材料上限、准确字节与无重复键，再解析材料进入原生载体。不能靠重新格式化材料绕过哈希。旧的未发布 v1 交接文件不接受新导入；已经保存的旧版本只按其原哈希认证读回。

可用载体包括：

- 原生二分类 LR：原生生产收据先认证源字节，再导出严格有限数值的 median imputer、StandardScaler、LogisticRegression 参数与特征顺序；接收端从已安装类型重建并进入原生 Experiment / ModelArtifact / 生产收据存储。远端 pickle 不反序列化。额外外部预处理、校准及其他模型家族当前明确不支持。导入实验没有伪造训练或验证指标，状态为 imported。
- 策略：准确 Strategy DSL，经原有解析器与构建器进入 StrategyRepository，不自动采纳或部署。
- Workflow：保留原发布者签名、工具声明、权限和准确版本，再经原有签名准入、模板与 PlanValidator 进入版本库；不建立第二套 runtime。

同一 origin/type/name/version 的内容不可重写。接收头以 CAS 推进，准确 envelope 重试只读回已经认证的同一版本；改变请求 ID 或重新签一个旧版本不能重复注册。回滚保留原有不可变版本，并确认目标权限与当前头版本；Workflow 原生头与交接头在同一数据库事务中改变。活动计划仍冻结其准确能力版本。

撤销节点前先读取影响提案，确认准确交接头及提案哈希。任一头变化均拒绝旧提案；撤销、停用头和撤销收据原子落账，重试幂等。旧版本列表只显示受管理员保护的 metadata。已撤销节点的版本不能通过后续原生读取或执行重新启用；已经开始的宿主调用不声称可被撤销动作追溯消除。

这套软件授权依赖可信宿主、数据库与应用代码。它不证明能防住同 UID 修改数据库/私钥/源码的恶意宿主，不替代机构 IdP、生产 registry、TLS 网关或跨机构授权。参考双进程验收只证明本机两个独立 workspace/process 的上述协议与原生载体。
