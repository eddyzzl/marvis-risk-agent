## 交付范围

这次改动优先解决报告编辑可靠性，再调整主要工作流和桌面视觉层级。延续静态 HTML/CSS/JavaScript 与 FastAPI，不新增前端框架，也不改变确定性验证算法。原有 Plugin / Tool / Hook / Workflow 执行与治理边界继续生效。

## 草稿保存与确认契约

- 新增 `PUT /api/tasks/{task_id}/agent/report-draft`，携带 `revision`、`draft_message_id`、`draft_edit_revision` 和 `text_values`。
- 仅接受既定报告叙事字段；指标字段不在可写范围。保存到当前草稿消息 metadata，复用现有本地数据库，无 schema 迁移。
- 使用 SQLite 事务核对当前待确认草稿、编辑版本、报告版本与活动作业。过期写入返回冲突，不静默覆盖其他窗口。
- 审计保存消息 ID、编辑版本和字段名，不复制正文到审计 detail。草稿不写入浏览器持久化存储或 Agent 记忆。
- 单份与批量确认继续使用原有生成链路；新版界面附带版本绑定。旧客户端未传绑定字段时保留兼容路径。
- 草稿保存失败时修改留在当前窗口；未保存离开有提示。只有服务器已保存的修改承诺刷新恢复。

## 验证记录

测试和浏览器均使用隔离的合成演示 workspace，不含真实客户数据。浏览器服务仅监听 `127.0.0.1`。

- 后端报告相关回归：`test_agent_api.py`、`test_validation_batch_api.py`、`test_report_texts_v2.py` 中报告与结论用例，66 项通过。
- 前端及受影响报告契约：`test_frontend_*.py`、`test_validation_report_copy.py`、`test_report_draft_persistence.py`，617 项通过，3 项环境条件跳过。最终策略文案与折叠调整另复测 80 项策略用例，全部通过。
- 新增检查覆盖：跨模型缓冲、保存中继续输入、失败保留与重试、版本冲突、两个并发写入只有一个成功、拒绝指标编辑、保存不产生确认或作业、批量保留各模型草稿。
- 浏览器实际操作：A/B 模型分别修改、保存、切换及刷新恢复；两个窗口同时编辑同一草稿，展示冲突差异，保留当前修改后保存并刷新恢复；方向键切换模型；报告切换视图及模型后恢复到相同滚动位置；1/3/10 模型创建窗口和缺项保留，十模型主按钮在 1000px 高窗口内，缺验证人员时自动展开第一模型并聚焦；策略默认 1 项操作、全部工具 35 项、搜索“阈值”返回 7 项；配置模型入口实际打开设置。
- 宽桌面实测：1440/1600/1920px 下中心分别为 858/1018/1338px；侧栏 256px、右栏 264px；页面宽度均与视口一致，无页面横向溢出。对照评审时 1600px 下中心 796px，增加 222px。
- 受影响 Python 的 Ruff、10 个 JavaScript 文件语法检查与 `git diff --check` 通过。末轮浏览器控制台无异常。

## 验证边界与后续验收

本次验证的是交互实现、本地持久化及受影响自动化契约。没有用真实业务材料执行 LLM、Notebook、PMML 打分、Word/Excel 生成或生产审批；本地测试通过不表示这些端到端流程已获业务验收。

评审中提出的真实用户五秒定位、任务用时/点击数比较、完整 VoiceOver 与逐项对比度检测，需要单独的使用评估。报告风险标红继续依赖平台已有证据与输出机制；本次没有从编辑文案推断通过/不通过，也未新增富文本风险判定器。材料自动提取建议的来源标识、完整报告预览与常用任务排序属于后续细化，不在本次已验证交互中宣称交付。

回滚时回退本分支代码即可；新增保存内容只是现有草稿消息的 metadata 字段，不需要回滚数据库结构。已经确认或生成的业务结果仍须遵循既有审计与重生成流程，不能通过代码回退抹除。
