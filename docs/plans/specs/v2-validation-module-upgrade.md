# V2 模型验证模块升级计划

状态：已实现，发布验证中。

依据：模型验证实际操作中发现的问题；人员和渠道示例已泛化。

相关规格：[v2-validation-batch-spec.md](v2-validation-batch-spec.md)、[docs/roadmap.md](../../roadmap.md)

## 1. 一句话目标

把已经做好的**单模型验证 Agent 工作台**扩展为可一次添加多个模型：欢迎页只保留「模型验证」；创建时可添加 1–N 套材料。只加一个则与现在单模型验证相同，不生成汇总 Excel；加了多个则同一套对话/步骤里按序验证，并多出一份汇总 Excel。

使用者理想路径：

```text
点击「模型验证」→ 创建对话框可添加多个模型（默认一个）
  → 单个模型在对话里说「开始验证」；多个模型创建后默认「自动审查」，按序自动执行
  → Agent 列出识别结果，用户只确认有歧义的项
  → 逐步看到每个模型的扫描 / 打分 / 指标 / 结论
  → 每套都有 Word/Excel；仅当模型数 ≥ 2 时再多一份汇总 Excel
  → 看完不满意，继续对话修改后重新生成
```

不另做一套验证算法，不把 9 个模型的 KS/AUC/PSI 压成 Agent 自由文本。

## 2. 本次真实验收里踩到的平台问题

这些问题都发生在真实路径上，不是合成测试。

| 问题 | 现象 | 根因 |
|---|---|---|
| 欢迎页拆成两个入口 | 「模型验证」和「批量模型验证」并列；批量进表格后台，点选合同/启动，右侧步骤和证据区被藏起来。父任务即使 `run_mode=agent`，发消息也会 501 | 创建与 `task_type` 按入口拆开。UI：`welcomeValidationBatchCard`；`app.js` 对 batch 隐藏 `progressRail` / notebook / metric。后端：`WIRED_AGENT_TASK_TYPES` 不含 `validation_batch` |
| 批量几乎看不见单模型成果 | 父任务只有总览表；`?task=parent&item=child` 只高亮行，不打开该模型的对话/图/指标 | 规格 §6 明确不把 child 提升为左侧当前任务；完整 Agent UX 要另选子任务 |
| 批量会自己写结论、自己出 Word | 子任务跑完后 `_write_report_conclusions` 直接生成并落 Word，用户没有单模型那种「确认结论」对话 | `marvis/validation_batch_runner.py` 把 Agent 对话门收成后台一步 |
| 封面占位符经常空着 | Word 留下 `{{TEXT:drafter}}` 等；页面「报告字段」看起来有值 | `GET /report-fields` 用 `default_report_values()` **展示**默认值；Agent 出 Word 只用库里已保存的 `report_values`。页面创建会写入撰写人/日期/样本定义，API/批量创建几乎不写 |
| 报告出完不能对话修订 | 任务 `succeeded` 后 `POST /report` 返回 409；本次只能在平台外改字段、本地重出 Word。用户看到 Word/Excel 不满意时，无法在对话里改完再生成 | 报告阶段只允许 `writing_artifacts` / `review_required`；Agent 没有「改文案 → 重出 Word/Excel」闭环 |
| 文案口径全写成授信 | T 卡概述和「申请授信的用户」都错 | 默认模板句是授信；工作区 Word 模板把「申请授信的用户」写死 |
| 字典缺 importance 时体验差 | 扫描直接失败；本次是外部操作者手工补列才继续，用户在对话里看不到「缺哪一列、怎么补」 | `feature_metadata.py` 把 importance 当必填（应保留）；缺的是 Agent/合同门上的明确补齐提醒，不是把该列改成可选 |
| Agent 闸门偏碎 | 每套要「开始 → 确认合同 → 继续打分 → 继续指标 → 继续结论 → 确认 Word」 | 低风险阶段也要用户说「继续」；批量更是每模型点一次合同表单 |
| 汇总 Excel 与运营表不一致 | 平台批次表偏审计（PMML/压力/完整性/子任务 ID）；本次实际要的是 KS×100 一位小数、PSI 两位、绿灯勾 | `validation_batch_excel.py` 与验证人员习惯表不是同一份 |

约束保持不变：Notebook 契约、PMML 对比、KS/AUC/PSI 由平台算；Agent 不能编造指标或跳过证据。

## 3. 这次是外部操作者在决策的事

2026-08-19 跑 9 套时，大量判断发生在 MARVIS 外面（对话里的编码助手 + 脚本 + 点选）。升级目标是：**这些判断尽量由平台 Agent 做建议，用户只拍板有歧义或有责任的项。**

### 3.1 决策清单与移交

| 这次谁在决定 | 具体内容 | 应交给谁 | 用户还要做什么 |
|---|---|---|---|
| 外部操作者 | 不用「模型验证(手动).ipynb」，选带 RMC 的 notebook | **平台扫描**按角色 + RMC 探测；多份 notebook 时 Agent 列出候选 | 仅在多份冲突时选一个 |
| 外部操作者 | 06/08 用 `数据字典.xlsx` 而不是 `数据字典_20260810.xlsx` | **平台**按「最新非备份 / 文件名不含日期后缀优先」排序，Agent 说明选了哪份 | 用户说「用另一份」才换 |
| 外部操作者 | 缺 `importance` 时在平台外手工补列才能扫描 | **平台扫描仍要求 importance 必填**；缺列时在对话和合同门写清「数据字典缺少 importance，请补充后重新扫描」，不要静默填 1.0，也不要把该列改成可选 | 按提醒补字典后继续 |
| 外部操作者 | 目标列 `y`，切分 `split_tag` 或 `model_flag`，时间 `loan_actv_dt` 或 `apply_dt`，PMML 输出 `probability_1` | **平台字段识别已有候选**；Agent 用一句话汇总建议，高置信且无冲突可走自动模式 | 冲突或低置信时确认一句 |
| 外部操作者 | 时间粒度选「日」还是「月」 | **平台**看列值形态（日期 vs `YYYYMM`）；仍写入合同 | 形态矛盾时确认 |
| 外部操作者 | 算法、是否跑 Notebook | V2 已是 PMML 打分、不跑训练 notebook；**不必再问用户** | 无 |
| 外部操作者 | 每步回复「继续」「确认」 | **Agent 自动模式**：扫描后、打分后、指标后自动进入下一阶段；只在合同歧义、结论草稿、出 Word 前停 | 每模型大约 1–2 次确认，而不是 5–6 次 |
| 外部操作者 | 撰写人/修订人先写成默认占位再改成实际验证人员 | **平台**用创建任务时的「验证人员」写入 `TEXT:drafter` / `TEXT:revision_author`，不要 LLM 猜名字 | 创建时填一次姓名 |
| 外部操作者 | 模型概述、适用范围、好坏样本句式；T 卡改成支用、A 卡保留授信 | **Agent 起草 + 用户确认**（见第 5 节） | 看草稿，说「按这个出」或改口径 |
| 外部操作者 | 客群名：自营通用T卡 / 渠道甲T卡 / 渠道乙 / 渠道甲、渠道乙 | **平台**从用户提供的模型名称解析；没有明确边界时留待用户补充，不维护机构硬编码名单 | 名称不含客群时补一句 |
| 外部操作者 | 任务已成功后用脚本本地重出 Word | **平台 Agent 报告修订闭环**：用户指出 Word/Excel 哪里不对，Agent 只改允许的叙事字段，确认后重新生成 Word **和** Excel，不必重跑打分 | 在对话里说改什么，确认后下载新报告 |
| 外部操作者 | 9 份报告下载 + 手写汇总 Excel | **仅模型数 ≥ 2** 时平台生成运营汇总表并支持打包下载；单个模型只出该模型 Word/Excel，不生成汇总 Excel | 无 |
| 必须留在用户 | 材料是否就是要验的这批；坏样本业务定义若材料里没有；最终是否签字采用 | 人 | 上传、确认歧义、看结论 |

### 3.2 用户操作应被压到什么程度

单模型：

```text
现在：创建 → 开始验证 → 填/点合同 → 继续打分 → 继续指标 → 继续结论 → 确认 Word → 若占位符空再改字段再出报告
目标：创建（带验证人姓名）→「开始验证」→ 合同无歧义则直接跑完并给出报告草稿 → 确认文案后出 Word/Excel → 若看完不满意，继续对话修改后再生成
```

多模型（创建时添加了 2 个及以上）：

```text
现在：另走「批量模型验证」卡片 → 表格里逐模型点确认合同 → 点启动批次 → 几乎看不到过程 → 分别下载
目标：仍点「模型验证」，在同一创建框里添加多个模型 → 同一套对话和步骤栏 → 创建后按自动审查逐个跑完（不必每个模型说「开始」「继续」）→ 合同有歧义才停下确认 → 切换查看每个模型结果 → 各模型 Word/Excel + 一份汇总 Excel
```

自动模式只处理**低风险、有平台证据**的节点（字段唯一匹配、下一阶段已扫描成功）。合同冲突、A/T 无法从名称判断、样本定义材料里没有、最终 Word 文案，仍要用户明确同意。这与现有「自动模式仅处理低风险节点」一致，不把验证做成无人值守投产。

## 4. 目标产品形态

### 4.1 工作台：与单模型 Agent 同一套壳

- 中间：对话 + 当前模型的扫描/打分/指标/结论区（现在批量把这些藏了）。
- 右边：步骤栏。单个模型仍是扫描 / 打分 / 指标 / 报告。多个模型时，批次级步骤（材料 → 合同 → 逐模型验证 → 汇总）下挂当前模型的扫描 / 打分 / 指标 / 报告。
- 不要用「点表格单元格」作为主路径。多个模型时，表格只作为总览附件，或结果区的模型切换条。

### 4.2 一个入口、可添加多个模型

欢迎页**只保留「模型验证」**，去掉独立的「批量模型验证」卡片。点击后打开同一个创建对话框：默认一行模型材料，可「添加模型」。

| 创建时模型数 | 用户看到的任务 | 报告 |
|---|---|---|
| 1 | 与现在单模型验证 Agent 相同（对话、步骤、证据区） | 该模型 Word + Excel。**不**生成汇总 Excel |
| 2–10 | 同一套工作台；可切换查看各模型结果 | 各模型 Word + Excel，**另外**一份不重算指标的汇总 Excel |

内部仍可用父/子任务隔离多套材料（合同、指标、报告各自一份）。对用户这是同一种「模型验证」任务，不是第二个产品。单个模型不要套一层空的批次壳，以免步骤栏和下载区出现「汇总待生成」。

- 用户始终停在当前验证任务的对话里。
- 多个模型时，子任务是执行单元；Agent 编排「正在验证 3/9 …」，并把该模型证据投影到中间区。

现有 `validation_batches` 表、顺序执行、单项失败不阻断、合同不静默确认，可以留给 **N≥2** 的实现。必须改的硬缺口：

- 把多模型任务接通 Agent API（`WIRED_AGENT_TASK_TYPES` 或消息路由到当前 child），否则对话发不出去。
- runner 不再跳过 continue / 结论确认门；阶段事件投影到父对话。
- UI 不再为多模型单独换成表格后台。

### 4.3 创建对话框

文件选择是唯一必要的点选。对话框在现有模型验证创建流上增加「添加模型」：

- 每行仍是模型名称/版本 + Notebook / 样本 / PMML / 字典。
- 验证人员只填一次，写进所有模型的撰写人/修订人。
- 只有一行时走现有 `POST /api/tasks`（或等价单模型创建），不要强迫走 `/api/validation-batches`。
- 两行及以上再走多模型创建 API。
- 上限仍建议 10；下限是 1，不再要求「批次至少 1–10 且必须当批次」。

## 5. 报告占位符：可以交给 LLM，但要分层

**可以，但现在几乎没接上。** `generate_word_conclusions` 只解析三键：`TEXT:pressure_test_summary`、`TEXT:pressure_impact_recommendation`、`TEXT:final_validation_conclusion`。概述、适用范围、好坏样本、撰写人都不在 LLM JSON 白名单里。批量创建子任务时 `TaskCreate` 不带 `report_values`，封面键库里是空的。这次空着的字段本来就该在出 Word 前由 Agent 填草稿，不该靠外部脚本 `PUT /report-fields`。

分层：

| 字段 | 谁填 | 规则 |
|---|---|---|
| 撰写人、修订人、日期、修订说明 | 平台 | 验证人员姓名 + 当天；LLM 不编姓名 |
| 模型概述、适用范围 | Agent 草稿 | 沿用句式；T 卡用「支用环节 / 支用申请阶段」，A 卡用「授信环节 / 授信申请阶段」；禁止「本模型模型」；客群从模型名解析 |
| 坏/好样本定义 | Agent 草稿 | 模板已有「正（坏）样本：」前缀，只填红字部分，如 `MOB6 逾期 >= 30 天` / `MOB6 未逾期`；MOB 从名称取，逾期天数材料或用户未给时默认 30 并标明假设 |
| 样本人群短语 | 平台或 Agent | 模板里「申请授信的用户」改为可替换：T 卡「申请支用的用户」，A 卡「申请授信的用户」 |
| KS/AUC/PSI、样本周期、训练比例 | 平台 | 继续走 `COMPUTED_REPORT_TEXT_KEYS`，LLM 不得改 |
| 压力说明、最终验证结论 | Agent 草稿 + 确认 | 已有 `generate_word_conclusions`；单模型要确认，批量不要再后台静默写入 |

实现要点：

1. 创建任务（含批量子任务）必须把封面身份字段写入库，与页面创建一致。
2. 指标完成后增加「报告文案草稿」阶段：LLM 只输出允许的叙事键；数字从 `validation_results` 注入提示词，禁止模型自己写 KS。
3. 用户在对话里确认（可改一句再确认）后才出 Word/Excel。
4. `GET /report-fields` 区分「库中实值」和「展示用默认值」，避免再出现「页面有字、Word 是 `{{TEXT:}}`」。
5. **报告修订闭环（Word 与 Excel 同等适用）**：任务在 `succeeded` / `review_required` 后仍可对话。用户说「概述改成支用」「坏样本写成 MOB6 逾期 >= 30 天」「把结论里的授信改掉」等，Agent 更新允许的叙事字段、展示草稿差异，用户确认后重新生成 Word **和** Excel。不重跑 PMML/指标。修订履历（修订人、日期、说明）由平台按这次确认更新。用户若要求改 KS/PSI 等确定性数字，Agent 拒绝并指向已计算证据。
6. 多模型任务（N≥2）里，对话默认改「当前正在看的模型」；用户点名「第 3 个」或模型名则切到对应子任务再修订、再出该模型报告；需要时再刷新汇总 Excel。单个模型没有汇总 Excel，修订只重出该模型 Word/Excel。

## 6. 分阶段交付

批准后按阶段改代码；未批准前不改 `docs/roadmap.md` 的已发布口径。

### 阶段 A — 单模型：少操作、报告能填满

- 创建即写入撰写人/日期；API 创建与 UI 创建同一套 `report_values`。
- Agent 在指标后起草概述/样本定义/A·T 口径，确认后出 Word/Excel。
- 修复「页面默认值 ≠ 库中值」。
- **成功后仍可对话改报告**：打开任务 → 指出 Word/Excel 不满意处 → Agent 改叙事草稿 → 确认后重出两份文件。验收至少覆盖「改概述/样本定义后新 Word 不含旧句、Excel 报告文本页同步、KS 数字不变」。
- 低风险阶段支持自动模式连跑（打分→指标），合同唯一匹配时可建议「按识别结果继续」而不是打开空下拉硬点。
- 字典 `importance` **保持必填**。缺失时扫描失败关闭，但 Agent 必须用可读文案指出缺列和补齐方式，禁止平台外手工造列、也禁止静默默认重要性。

验收：用这次 9 套里的 1 个 T 卡、1 个 A 卡，从欢迎页**「模型验证」**创建（只加一个模型）到 Word，不出现 `{{TEXT:}}`，T/A 口径正确，用户确认次数 ≤ 2，**没有**汇总 Excel。

### 阶段 B — 入口合并 + 多模型同一套 Agent 壳

- 欢迎页去掉「批量模型验证」卡片；只留「模型验证」。创建对话框默认一行，可「添加模型」。
- 一行提交走单模型创建；两行及以上走多模型编排。
- 多模型任务显示对话、步骤栏、当前模型证据区；不再隐藏 `progressRail` / notebook / metric。
- 模型切换（对话说「看第 4 个」或顶部分段）只切换投影，不把子任务变成左侧当前顶层任务。
- 多模型 runner 不再跳过结论确认；每个子任务走与单模型相同的阶段事件，投影到对话。
- 多模型任务接通 Agent API（`WIRED_AGENT_TASK_TYPES` + `agent/start` / `messages`）。

验收：欢迎页没有批量卡片。添加 2 个模型创建后，工作台看起来像模型验证 Agent，能看到第一个模型的图和指标，并能下载汇总 Excel。只加 1 个模型时工作台与现在单模型一致，下载区没有汇总 Excel。

### 阶段 C — 对话编排替代逐项点选

- 「请确认 9 个合同」改为 Agent 按序（或高置信打包）陈述建议映射，用户回「都按这个」或指出某一个改列。
- 去掉「必须点行内确认合同才能启动」作为唯一路径；表单可留作展开核对，主路径是对话。
- 单项失败继续下一个；父对话清楚说出失败原因和下一步。

验收：9 模型批次在合同无冲突时，用户不必点 9 次「确认此模型字段」。

### 阶段 D — 下载与汇总

- 单个模型：只提供该模型 Word/Excel，**禁止**生成或展示汇总 Excel。
- 多个模型：一键打包全部 Word/Excel，并生成汇总 Excel。
- 汇总 Excel 对齐运营习惯：标题「模型验证：YYYY年M月验证N个模型」；列含模型版本、有效性 KS（行业口径×100，一位小数）、稳定性 PSI（两位）、一致性/可复现性/完整性绿灯；不重算指标。
- 可选第二张表：Agent 批次综述（只引用已落库数字，带模型 task_id）。
- 某个子模型对话修订并重出报告后，可按需刷新汇总 Excel，不重算该模型指标。

验收：N=1 无汇总文件；N≥2 与 2026-08-19 手写汇总表同结构，数字与各模型 `validation_results.json` 一致。

## 8. 明确不做

- 不让 LLM 计算或改写 KS/AUC/PSI/分数一致性。
- 不自动把某个模型标成冠军或可投产。
- 不并行打分到抢同一套 UI 证据（可以后再做后台并行，第一版仍顺序）。
- 不把验证人员姓名、最终采用结论交给模型编造。
- 不为了少点一次而静默确认互相冲突的字段映射。
- 不把数据字典 `importance` 改成可选，也不允许扫描时静默填 1.0。
- 不为单个模型生成汇总 Excel，也不在欢迎页保留「批量模型验证」第二入口。

## 9. 建议的批准口径

1. 欢迎页只保留「模型验证」。创建时可添加多个模型：1 个走现有单模型验证且不生成汇总 Excel；2 个及以上同一套 Agent 工作台，并多一份汇总 Excel。
2. 平台 Agent 接管本次外部操作者做过的材料选择、合同建议、阶段连跑、报告起草和汇总下载；用户只确认歧义和终稿。
3. 报告叙事字段由 LLM 起草、人确认；身份字段和指标仍由平台写。看完 Word/Excel 不满意时，继续和 Agent 对话修改并重新生成，不重跑验证计算。
