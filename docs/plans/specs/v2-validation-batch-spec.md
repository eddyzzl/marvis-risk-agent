# V2 模型验证多模型规格

## 1. 目标与产品边界

多模型验证**不是**独立首屏入口。欢迎页只保留「模型验证」；创建对话框默认一行材料，可「添加模型」。

| 创建时模型数 | 用户看到的任务 | 报告 |
|---|---|---|
| 1 | 现有单模型验证 Agent 工作台 | 该模型 Word + Excel，**不**生成汇总 Excel |
| 2–10 | 同一套对话/步骤栏/证据区；内部用父/子任务隔离 | 各模型 Word + Excel，**另外**一份不重算指标的汇总 Excel |

它复用单模型验证的扫描、PMML 打分、确定性指标和报告链，不建立第二套验证算法。N≥2 时内部仍走 `validation_batches` 编排表。

批次的职责是编排、隔离、恢复和汇总：

- 每套材料创建独立的 `validation` 子任务，保留各自的状态、合同、证据、Word 报告和 Excel 分析报告。
- 父任务保存批次成员关系、整体进度和（仅 N≥2）汇总 Excel，不把单模型事实压平为自由文本。
- 子任务按创建顺序执行；当前版本不并行打分到抢同一套 UI 证据。
- 多个模型创建后默认「自动审查」：不必对每个模型再说「开始」或「继续」。合同无歧义时按唯一识别结果自动确认并连跑；有冲突时停在当前模型，确认后再继续后续模型。
- 单个子任务失败不得阻断后续子任务。
- 无冲突合同时仍可在对话里回复「都按这个」按识别结果确认；有歧义时指出某一个改列。表单可留作展开核对。
- 不自动选择冠军模型，不把 OOT KS 排名解释为可投产，也不替代独立验证人员结论。
- 旧的非 Agent `run_validation_batch` **不得**跳过结论确认门、不得后台静默写 Word。N≥2 出 Word 走各子任务 Agent job（自动审查会按单模型自动审查口径确认结论并出报告）。

旧的独立「批量模型验证」欢迎卡已删除。既有终态批次任务仍可打开下载 Word/Excel/汇总，不再作为新任务的创建入口。

## 2. 创建合同

N=1 走现有 `POST /api/tasks`（或等价单模型创建），不要套一层空的批次壳。

N≥2 走 `POST /api/validation-batches`，接收批次名称（用第一个模型名称）、验证人员和 2–10 个 item。每个 item 必须显式提供：

- 模型名称与可选版本；
- Notebook、样本、PMML 和数据字典四个明确文件角色。

第一个模型的四类文件从统一创建对话框的上传区按角色分类；后续模型各自四类上传。不得把第二个模型的文件复制给第一个模型。

平台必须对路径做规范化和材料角色校验。同一批次内任意两个角色不得复用同一个文件路径。创建失败时不保留半个父任务或孤立的批次目录。

当前多模型运行模式固定为 `agent`，并接通 `WIRED_AGENT_TASK_TYPES`。指标、状态和最终批次 outcome 由平台代码确定。

## 3. 状态机与确认门

父批次状态：

```text
created -> running -> awaiting_confirmation -> running
                                      \-> completed
                                      \-> partial_failure
                                      \-> failed
```

Agent 工作台（N≥2 的产品主路径）创建后默认「自动审查」，按 ordinal 逐个启动子任务 Agent job。合同无歧义时自动确认并连跑打分/指标/结论/报告；有冲突时当前模型进入 `awaiting_confirmation`，确认后再继续后续模型。刷新未完成批次会续跑，已完成批次不会重跑。

旧的 `POST /api/validation-batches/{id}/start` runner 仍按 ordinal 扫描所有可运行子任务，需要用户确认的子任务进入 `awaiting_confirmation`，且不得静默确认合同、不得静默写 Word。那条路径不再是 Agent 工作台的创建后自动执行入口。

运行期间，父任务的 `active_job_kind` 必须保持 `validation_batch`。详情轮询先看到终态、但父任务 job 尚未关闭时，前端不得提前清除 busy 状态。

## 4. 执行、失败隔离与恢复

合同 ready 的子任务复用单模型验证的可恢复阶段：

1. `scan`
2. `pmml_scoring`
3. `metrics`
4. 与单模型相同的结论草稿；自动审查下按单模型自动审查口径确认并出报告
5. 合同有歧义或用户主动停下时，确认后再继续该模型 Word/Excel

每个 item 的 stage、错误代码和经过边界处理的公开错误文案独立持久化。异常只将当前 item 标为 `failed`，循环继续下一项。

进程在 queued job 尚未开始或运行中意外退出时，startup recovery 必须结束活动 job、释放父任务 busy 状态，并把批次收敛到可解释且可重试的失败状态。公开错误不得泄漏受允许材料根目录之外的绝对路径。

## 5. 结果与下载合同

每个完成 item 保留现有单模型下载地址：

- `validation_report.docx`：Word 验证报告；
- `validation.xlsx`：结构化分析与指标报告。

**仅当模型数 ≥ 2** 时，父任务原子生成 `validation_batch_summary.xlsx`。汇总只消费已持久化的子任务结果，不重算指标。工作簿含两张表：`模型验证汇总`（审计门禁、人工校验链接）和 `运营汇总`（与验证人员习惯表同结构：标题「模型验证：YYYY年M月验证N个模型」；有效性 KS 行业口径×100 一位小数、稳定性 PSI 两位、一致性/可复现性/完整性绿灯）。N=1 不得生成或展示汇总 Excel。

批次终态规则：

- 全部 item 通过或仅需人工复核：`completed`；父任务有复核项时为 `review_required`。
- 至少一个失败、但并非全部失败：`partial_failure`，父任务为 `review_required`。
- 全部 item 失败，或汇总报告生成失败：`failed`。

无论批次终态为何，已经成功生成的单模型报告都必须保留。汇总失败不得删除或覆盖这些报告。

## 6. 前端交互合同

- 欢迎页只保留「模型验证」卡片；创建对话框可添加模型。
- N=1 不出现「汇总待生成」。
- 多模型任务显示对话、步骤栏、当前模型证据区；不再隐藏 `progressRail` / notebook / metric。
- 表格只作为总览附件；不要用「点表格单元格」作为主路径。
- URL `?task=<parent>&item=<child>` 只聚焦匹配行/投影，不把 child 提升为左侧当前顶层任务。
- 删除、通用扫描或通用材料修改不得破坏父子 membership。

## 7. 安全与验收

发布前至少验证：

- N=1 不走批次壳、无汇总 Excel；N≥2 才创建批次并生成汇总；
- schema 拒绝超过 10、额外字段和不完整材料；
- 路径边界、符号链接输出目录、重复材料路径和公开错误脱敏；
- 多 item 固定顺序、单项失败继续、部分失败只重试失败项；
- 无冲突合同时自动确认；有冲突失败关闭且不静默选列；对话「都按这个」仍可用；
- 单模型 Word/Excel 全部保留，汇总 Excel 可下载且不重算确定性指标；
- 父任务 active job 生命周期、崩溃恢复和重复启动冲突；
- 宽桌面真实浏览器完成：欢迎页单入口、添加模型、对话确认、运行、逐项下载、汇总下载。

真实材料、独立验证签字、原生 Windows 文件占用和生产调度不由本规格的合成测试或本地浏览器纵切证明。
