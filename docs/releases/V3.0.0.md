# MARVIS V3.0.0

[中文](#中文) · [English](#english)

## 中文

V3 将进度、材料、确认、结果与下一步集中到同一个桌面工作台，让本地风控分析更容易跟进、复核和交付。

### 用户能直接感受到的变化

- **更清晰的任务工作台**：侧栏按“需要你”“进行中”“最近”分组；任务进度、材料、结果、报告和后续动作集中呈现，长任务名称与状态更容易辨认。
- **中英文与明暗主题**：设置中可即时切换界面语言和主题。用户自己的任务名、文件名、字段名与原始数值保持原样；界面刷新保留未发送草稿的回复语言提示和报告编辑状态。
- **有下一步的诊断与恢复**：模型、特征和策略的诊断卡提供明确选择、处理记录、预算、任务环境覆盖及可用的撤销操作。安装依赖仍提供操作说明，由用户执行。
- **对话连接取数与监控**：从对话发起 SQL 取数或监控调度，在业务表单中复核确认。切换监控数据集时，时间和标签字段同步刷新，仍有效的编辑继续保留。
- **更顺畅的建模交接**：月度样本成熟期、分数方向冲突、调参确认、模型交接名称和报告文案更清晰；字段别名进入建模与特征分析，历史材料映射扩展到数据处理。
- **报告确认更可靠**：过期版本不能留下已排队任务或确认记录；丢失成功响应后可读取已有结果。催收与反欺诈需求提供现有能力的明确入口指引。
- **图表和下载更易读**：报告下载按钮在中英文、明暗主题及悬停/键盘聚焦状态下保持清晰对比度；自动树导出改善符号、长标签和指标排版，同时保留原始字段、数值与字体身份。

新版界面与合成数据演示截图见 [中文 README](../../README.zh-CN.md)。

### 正确性与执行改进

- 规划与复核保留用户原始限制和阈值；策略编译、网页搜索复用出站检查。
- 盲 OOT、时间事实采集与结论门控接通。材料可得时间、参数来源或标签成熟度缺少证据时，继续标记为未知；测试集参与选模时明确披露。
- 验证、特征、组合趋势、Vintage 和建模的参考复算扩展到声明支持的配置，包括校准、集成、CatBoost、MLP、评分卡、权重与提前停止；不支持的配置失败关闭。
- macOS Notebook 设置不可读时失败关闭；补齐 loopback/API 令牌、AF_UNIX、解析器、子进程和原生 Agent/双模型旅程检查。修复 macOS 26 隔离环境中 JVM 本机通信被误拦的问题，外网限制保持有效。CI 配置独立 macOS 检查，跳过不计为通过。
- 冻结性能负载与隐藏基准入口支持输入绑定、完整尝试预算、进程预热、并发及故障原件。未知执行效果、未恢复结果与失败记录继续保留。
- 收拢公共结构校验、隔离算法文件副作用，并补充取消传递、任务间前端状态隔离和行为回归。

### 兼容与验收边界

V1 Notebook 契约、手动和 Agent 模式、Notebook 内存模型分与 PMML 分比较，以及确认后的 Word/Excel 和多模型汇总保持兼容。标准 V2 验证路径仍只静态读取 Notebook，PMML 在宿主 JVM 评分；“V1/V2”在这里指兼容的执行路径。

Notebook 网络模式不等于整个应用隔离。Windows/Linux 的原生隔离、同 UID 恶意进程与 root 不在已声明的 macOS 原生隔离保证内。第三方 learner 拟合复现、PMML 压力语义、叙事正确性与业务效果各自保留支持边界。

**软件发布、正式软件验收 S、历史业务效果 H、机构生产 P 分别判定。** 真实模型付费基准仍需模型配置和费用上限；历史评测仍需独立脱敏原件与未暴露的 OOT 期间；机构生产仍需真实接口、身份、批准流量、SLO 和责任人签字。本次发布不将这些外部条件宣布为已满足，也不改变旧历史比较未达门槛的结论。

隐藏基准的 133 个案例模板、193 个槽位与 54 项人工验收清单是执行准备材料；协议替身 dry run 不等于真实模型评测，空白清单不等于人工签字。完整状态见 [能力验收状态](../capability-status.md)。

## English

V3 brings progress, materials, confirmations, results, and next actions into one desktop workspace, making local risk analysis easier to follow, review, and deliver.

### What users will notice

- **A clearer task workspace:** tasks are grouped into Needs you, In progress, and Recent. Progress, materials, results, reports, and follow-up actions stay together, with clearer long titles and status labels.
- **English and Chinese, light and dark:** switch the interface language and theme in Settings. Your task names, filenames, field names, and original values stay unchanged. Interface refreshes preserve unsent reply-language hints and report editing state.
- **Diagnostics with a next action:** modeling, feature, and strategy recovery cards offer explicit choices, action history, budgets, task environment overrides, and undo where available. Dependency installation remains an action for the user to perform.
- **Conversation-connected extraction and monitoring:** start SQL extraction or a monitoring schedule from a conversation, then review and confirm the business form. Switching a monitoring dataset refreshes time and label fields while preserving valid edits.
- **Smoother modeling handoffs:** clearer monthly sample maturity, score-direction conflicts, tuning confirmation, model handoff names, and report wording. Field aliases are available in modeling and feature analysis; historical material mapping also covers data processing.
- **More reliable report confirmation:** stale revisions cannot leave a queued job or confirmation record behind, and completed results can be read back after a lost response. Collections and fraud requests get explicit guidance to supported entry points.

- **More readable exports and downloads:** report buttons retain readable contrast across languages, themes, hover, and keyboard focus. Automatic-tree exports improve symbols, long labels, and numeric formatting while retaining original fields, values, and font identity.

See the [English README](../../README.md) for the new interface and screenshots using synthetic demonstration data.

### Correctness and execution improvements

- Planning and review retain the user's original constraints and thresholds. Strategy compilation and web search share outbound checks.
- Blind OOT evaluation, temporal facts, and conclusion gates are connected. Unproven availability times, parameter sources, and label maturity remain unknown; model selection that uses a test set is disclosed.
- Reference recomputation for validation, features, portfolio trends, Vintage, and modeling covers explicitly supported configurations, including calibration, ensembles, CatBoost, MLP, scorecards, weights, and early stopping. Unsupported configurations fail closed.
- macOS Notebook execution fails closed when settings cannot be read. Additional checks cover loopback/API tokens, AF_UNIX, resolvers, subprocesses, and native Agent/multi-model journeys. JVM loopback compatibility on macOS 26 is repaired while external networking remains restricted. CI includes a separate macOS check; skipped checks do not count as passes.
- Frozen performance and hidden-benchmark runners bind inputs, reserve budgets for all attempts, and retain process warm-up, concurrency, and fault evidence. Unknown effects, unrecovered outcomes, and failures remain visible.
- Shared structural validation, algorithm file-side-effect boundaries, cancellation propagation, per-task frontend state, and behavior regression coverage have been strengthened.

### Compatibility and acceptance boundaries

The V1 Notebook contract, manual and Agent modes, Notebook in-memory versus PMML score comparison, confirmed Word/Excel reports, and multi-model summaries remain supported. The standard V2 validation path still reads Notebooks statically and scores PMML in the host JVM; “V1/V2” here names the compatible execution paths.

Notebook network mode does not isolate the entire application. Native isolation on Windows/Linux, malicious same-UID processes, and root are outside the stated macOS isolation guarantee. Third-party learner refits, PMML stress semantics, narrative correctness, and business outcomes each retain their own support boundaries.

**Software release, formal software acceptance S, historical business evidence H, and institution production acceptance P are separate decisions.** Paid-model benchmarks still require model configuration and a spending cap. Historical evaluation requires independent de-identified originals and unexposed OOT periods. Production acceptance requires real interfaces, identity, approved traffic, SLOs, and responsible-party sign-off. This release does not declare those external conditions satisfied or revise earlier historical comparisons that missed their thresholds.

The 133 hidden-scenario templates, 193 execution slots, and 54-item manual checklist prepare the evaluation process. A protocol-substitute dry run is not a real-model benchmark, and an unsigned checklist is not acceptance. See [capability status](../capability-status.md) for the full ledger.
